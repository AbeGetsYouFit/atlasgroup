# Atlas Group website

A complete local website built around the approved modern Atlas identity: electric blue, ink navy, outlined ATLAS GROUP logo, restrained typography, and cinematic Michigan-inspired artwork.

## Structure (updated September 22, 2026)

Atlas Group is the parent brand. Four affiliated companies sit under it, each with its own lockup (same emblem and ATLAS letterforms, company name in place of GROUP) and its own page:

| Company | Route | Inquiry value |
| --- | --- | --- |
| Atlas Properties | `/properties` | Real estate |
| Atlas Insurance | `/insurance` | Insurance |
| Atlas Mortgage | `/mortgage` | Mortgages |
| Atlas Construction | `/construction` | Construction |

Old routes `/real-estate` and `/mortgages` redirect (301 in production, client-side in dev). Lockup SVGs are generated by `../branding/atlas-group/vector/build_lockups.py`, which writes into `public/brand/` — do not hand-edit those files.

The homepage and About page include a founder section (Adam Hage, photo in `public/media/adam-hage.webp`) listing license **types** only. License numbers, the public phone, and the public email are still to be supplied; see `src/content.ts` (`founder`) and `.env.example`.

## Preview deployment (GitHub Pages)

Live preview: **https://hhage-pro.github.io/atlasgroup/** (repo `hhage-pro/atlasgroup`, branch `gh-pages`). It is a static build: pages are pre-rendered, `noindex` stays on, and the inquiry form is shown in "design preview" mode (not connected). Redeploy after changes:

```sh
BASE_PATH=/atlasgroup/ VITE_STATIC_PREVIEW=1 npm run build
cd dist && touch .nojekyll && git init -q && git checkout -q -b gh-pages && git add -A && git commit -qm "Deploy preview build" && git push --force https://github.com/hhage-pro/atlasgroup.git gh-pages && cd .. && rm -rf dist/.git
```

`BASE_PATH` makes asset URLs and the router base-aware (see `vite.config.ts`, `src/content.ts` `asset()`, `src/main.tsx`, `src/entry-server.tsx`). Omit both variables for the normal Express build. `design/original-artwork/` is gitignored (70 MB of generation originals); it lives only on this Mac.

## Run

Requires Node.js 22.13 or newer.

```sh
npm ci
npm run dev
```

Development preview: `http://127.0.0.1:4173`.

```sh
npm run build
npm start
```

The production server uses port 4173 by default. Set `PORT=4174` to run beside development. Set `HOST` only when configuring a deployment. The server loads an optional `.env` file.

## Inquiry delivery

With no mail configuration, the form explicitly operates in **local preview mode**. It saves inquiries as private JSON files in `data/inquiries/`; it does not send them to Atlas. This folder is gitignored and excluded from the source archive.

Copy `.env.example` to `.env` and supply the approved SMTP account, sender, and recipient through local environment configuration to enable email delivery. `PUBLIC_EMAIL` and `PUBLIC_PHONE` populate visible contact links. `PUBLIC_ORIGIN` is the expected public origin when running behind a proxy. Do not commit credentials. No email credentials, public phone number, or inbox destination were supplied during this build, and live delivery has not been tested.

Once all SMTP settings are present, the server sends inquiries to `INQUIRY_TO` with the visitor’s email as `Reply-To`. It reports success only after the mail transport accepts the message. Preview mode must not be used to collect unattended public leads.

### Lead capture (GoHighLevel)

With `GHL_PIT_TOKEN` and `GHL_LOCATION_ID` set, `POST /api/leads` upserts a visitor into the Atlas Group GHL sub-account the moment a valid phone or email is entered (the forms call it on blur, debounced). A finished inquiry clears the `partial-lead` tag. `/api/config` reports `captureMode: "ghl"` when it is on; in production without the vars it is `"off"` and the boot log says so loudly. Locally without the vars the endpoint answers `{preview:true}` and logs the payload instead of creating contacts.

## Content and launch settings

- The site is a **local review build**, not a public deployment. `noindex,nofollow` is deliberately enabled until business details and publication are approved.
- Review business entity names, public contact details, service availability, relevant license information, privacy practices, and final marketing copy before publishing. No fabricated license identifiers, team biographies, testimonials, sales figures, loan rates, or listings are included.
- The generated imagery is illustrative. It is not a portfolio of Atlas projects or an inventory of properties for sale; this is disclosed in the footer.
- Set the final domain, absolute social-sharing image URL, canonical URLs, and sitemap as part of deployment. Remove `noindex` only when the business is ready to publish.
- The form is an initial contact request, not an insurance binder, mortgage application, or project estimate. No sensitive-document upload is included.

## Artwork and provenance

All new photographic artwork and the cinematic clip were generated using **Higgsfield**:

- Soul Location: hero home, interior, neighborhood, construction, insurance, mortgage, and About-panorama scenes. On September 22, 2026 the construction scene was regenerated as a framed addition beside a brick house, the interior was regenerated warmer, and dedicated insurance (brick colonial at dusk after rain; a generated yard sign was cropped out), mortgage (morning kitchen with keys) and About-panorama (golden-autumn home; background cars removed with Nano Banana 2) scenes were added so no two sections share an image. Earlier versions are kept in `design/original-artwork/` with `-v1` suffixes.
- Seedance 2.0: eight-second 1080p source film using the generated hero home as its first frame.
- Film prepared as a smooth forward/reverse 16-second silent loop, 1600 × 900, about 3.7 MB. Stills compressed to WebP; original outputs retained in the local design folder.
- GPT Image 2 through Higgsfield: four coordinated section design concepts.
- Website branding uses the existing user-approved vector logo plus four division lockups built from the same glyph set. The founder portrait is a supplied photograph, not generated. UI text and controls are real HTML/React, not images.

`design/asset-prompts.json`, `design/*-job.json`, and `design/design-spec.md` document generation and design decisions. `scripts/generate_assets.py` is a generation helper that can spend provider credits; do not run it as part of ordinary development.

## Architecture

- `src/App.tsx`: pages, hero playback, service explorer, route behavior.
- `src/components.tsx`: navigation, branding, footer, inquiry form.
- `src/content.ts`: service page copy and FAQ content.
- `src/styles.css`: responsive visual system.
- `server.mjs`: local/production hosting and inquiry API.
- `server/inquiries.mjs`: input validation and rate limiting.
- `scripts/prerender.mjs`: pre-rendered production pages.

## Verification

`npm run build` checks TypeScript, builds optimized assets, and pre-renders the pages. `npm test` covers inquiry validation and rate-limit behavior. Browser testing covers route loading, service switching, inquiry preselection and local-save confirmation, mobile menu/Escape, required fields, hero controls, and reduced motion.

The initial in-app browser checks succeeded for interactions; its viewport capture produced incorrectly scaled mobile screenshots. A separate Playwright Chromium pass was used for accurate responsive screenshots at 1440, 768, 390, and 320 pixels, plus a 2688-pixel wide-screen check. Live SMTP delivery, public hosting, and physical-device Safari are not verified.
